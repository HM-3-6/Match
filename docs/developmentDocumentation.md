## 1. 项目概览

“行·迹”是一个以红色文化旅游为主题的资讯与互动平台。当前版本以静态页面为主，覆盖路线推荐、红色故事、景点预约、地图路线演示和后台管理演示等场景。

### 1.1 功能矩阵

| 模块       | 能力                                               | 当前状态 |
| :--------- | :------------------------------------------------- | :------- |
| 首页       | 平台介绍、栏目导航、路线推荐、云打卡、景点推荐     | 可用     |
| 精选路线   | 4 条主题路线，数据驱动渲染，跳转地图演示页         | 可用     |
| 红色故事   | 6 组“新旧对比”滑块卡片，跳转 6 个故事详情页        | 可用     |
| 云打卡     | 3 张景点轮播图 + 预约系统入口                      | 可用     |
| 地图演示   | 高德地图路线、控件、范围限制、标记拖拽、节点打卡   | 可用     |
| 故事详情   | 6 个独立静态详情页，介绍历史背景与精神内涵         | 可用     |
| 景点预约   | 选择景点、填写预约信息、成功弹窗                   | 前端演示 |
| 管理后台   | 数据看板、地点/打卡/调研/系统设置                  | 前端演示 |
| 登录注册   | 表单校验、密码显隐、模拟登录/注册                  | 前端演示 |

### 1.2 核心用户路径

## 2. 技术栈与运行方式

### 2.1 技术栈

| 技术               | 引入方式                  | 用途                               |
| :----------------- | :------------------------ | :--------------------------------- |
| HTML5 / CSS3       | 原生                      | 页面结构、布局、动画               |
| JavaScript（ES6+） | 原生                      | 数据渲染、交互、地图逻辑           |
| 高德地图 JS API    | 本地 `maps.js`            | 路线、标记、信息窗体、地图控件     |
| Chart.js           | 本地 `chart.js`           | 管理后台柱状图                     |
| Font Awesome 6     | CDN（仅登录/注册页）      | 表单图标                           |
项目没有 `package.json`、构建脚本、包管理器和后端服务，所有页面均可直接由静态服务器托管。

### 2.2 本地运行

在**项目根目录**启动静态服务器：

```bash
cd C:\Users\acy_1\Desktop\Match
python -m http.server 8000
```

然后访问：

```text
http://localhost:8000/src/index.html
```

> **路径注意事项**
>
> `src/index.html` 和 `src/adminConsole.html` 使用了 `../src/static/...` 这类相对路径，默认以**项目根目录**为站点根。若把 `src/` 直接作为站点根启动服务，这些路径会解析成 `/src/static/...` 并 404。建议保持“项目根目录启动”的方式，或在后续重构时统一改为 `./static/...`。
>
> 直接双击 `src/index.html` 也能加载大部分样式和脚本，但高德地图涉及域名白名单与网络请求，仍建议通过 HTTP 访问。

### 2.3 浏览器与网络要求

- 推荐使用较新的 Chrome / Edge。
- 页面使用了 CSS 变量、`clip-path`、`:has()`、Grid、`backdrop-filter` 等特性，旧版浏览器可能出现样式降级。
- `maps.js` 为本地打包的高德 SDK，但地图瓦片、地理编码等服务仍需联网。
- 登录/注册页的 Font Awesome 来自 CDN，离线时会丢失图标。

## 5. 首页实现说明

### 5.1 页面结构


栏目导航使用锚点定位：

| 导航项                   | 目标 ID        |
| :----------------------- | :------------- |
| 精选旅游路线             | `#route`       |

### 5.2 精选旅游路线：`routeList.js`

路线数据集中在 `ROUTE_DATA` 数组中，由 `routeList.js` 一次性拼接为 HTML 写入 `.route-list`。

#### 数据结构

| 字段       | 类型     | 必填 | 说明                                       |
| :--------- | :------- | :--- | :----------------------------------------- |
| `badge`    | string   | 是   | 卡片左上角主题标签，如“革命摇篮”           |
| `name`     | string   | 是   | 路线名称                                   |
| `desc`     | string   | 是   | 一句话简介                                 |
| `tags`     | string[] | 是   | 路线标签，如“党性教育”“山岳景观”          |
| `stops`    | string[] | 是   | 行程节点，首尾自动标记为起点/终点          |
| `days`     | string   | 是   | 行程天数，仅数字部分                       |
| `stay`     | string   | 是   | 住宿描述，如“天2晚”                        |
| `audience` | string   | 是   | 适合人群                                   |
| `short`    | string   | 是   | 简称，供无地图路线按钮的 `data-short` 使用 |
| `map`      | string   | 否   | 地图演示页地址；存在时按钮为 `<a>`         |

#### 渲染流程

1. `renderRouteList()` 查询 `.route-list`，不存在则直接返回。
2. 对 `ROUTE_DATA` 逐项调用 `buildRouteItem()`。
3. 生成 `.route-item` 卡片：信息区、节点路径区、底部信息与按钮。
4. 通过 `innerHTML` 一次性插入，减少 DOM 操作。
5. 在列表上绑定一次点击事件，使用事件委托处理 `.route-btn`。

当前 4 条路线均配置了 `map`，所以“查看详情”全部是链接。事件委托中的 `window.showToast` 分支目前不会触发；同时首页并未定义 `showToast`，只有 CSS 中的 `.toast` 样式，属于预留逻辑。

#### 样式要点

- `.route-list` 为两列 Grid，间距 18px；`max-width: 1100px` 以下改为单列。
- `.route-item` 使用左侧 4px 红色渐变装饰条、悬浮上移与阴影。
- 节点连线由 `.path-node::before` 分段绘制，首尾节点使用不同颜色。
- 768px 以下进一步压缩内边距、字号，按钮变为整行。

### 5.3 红色故事区：`splicing.js`

#### 数据结构

| 字段      | 类型   | 说明                         |
| :-------- | :----- | :--------------------------- |
| `oldImg`  | string | 历史旧照文件名               |
| `newImg`  | string | 今日实景文件名               |
| `date`    | string | 时间标签                     |
| `title`   | string | 事件标题，同时作为图片 alt   |
| `link`    | string | 详情页地址                   |

`redStories` 中的图片路径统一拼接为 `./static/image/${文件名}`，因此新增图片必须放在 `src/static/image/` 下。

#### 渲染与交互

1. `redStoryHtml` 将 6 条数据拼接为 `.slider-box` 卡片。
2. 写入 `#redStoryGrid`。
3. 遍历每张卡片，初始化 CSS 变量 `--percent`。
4. 监听 `.slider-input` 的 `input` 事件，实时更新 `--percent`。

新旧图片叠放与裁剪完全由 CSS 完成：

```css
.img-now {
    position: absolute;
    inset: 0;
    clip-path: polygon(var(--percent, 50%) 0, 100% 0, 100% 100%, var(--percent, 50%) 100%);
}
```

中间的 `.line` 使用 `left: var(--percent)` 跟随滑块。滑块使用原生 `input[type="range"]`，因此支持键盘方向键操作。

#### 响应式

- 1200px 以下：3 列变 2 列。
- 900px 以下：左右两栏改为上下排列，故事卡片仍保持 2 列。
- 700px 以下：故事卡片变为 1 列。
- 图片区固定高度 220px，使用 `object-fit: cover` 保证不拉伸。

### 5.4 云打卡：纯 CSS 轮播

当前“云打卡”并不是真正的打卡记录系统，而是：

- 3 张景点图片的单选框轮播；
- 一个跳转到 `红色景点预约系统.html` 的按钮。

实现方式：

```html
<input type="radio" name="cloudSlider" id="cloudSlide1" checked>
<input type="radio" name="cloudSlider" id="cloudSlide2">
<input type="radio" name="cloudSlider" id="cloudSlide3">

<div class="radio-slides">...</div>
<div class="radio-nav">
  <label for="cloudSlide1"></label>
  <label for="cloudSlide2"></label>
  <label for="cloudSlide3"></label>
</div>
```

`lunbotu.css` 通过 `#cloudSlide1:checked ~ .radio-slides` 等选择器横向位移，实现无 JS 轮播。使用独立的 `name="cloudSlider"` 和 `cloudSlide1~3`，避免与页面中其他轮播的单选框组冲突。

> 代码注释中提到的“数字勋章”尚未实现。若后续要补打卡与勋章，需要新增状态管理、打卡记录存储和勋章规则，不能只靠现有轮播。

## 6. 地图路线组件

### 6.1 组成

| 文件             | 职责                                                         |

### 6.2 `initMapDemo(config)` 配置结构

```js
initMapDemo({
  name: '井冈山',
  center: [114.118145, 26.510976],   // [经度, 纬度]
  zoom: 10,
  limitSW: [113.85, 26.2],           // 显示范围西南角
  limitNE: [114.39, 26.82],          // 显示范围东北角
  route: [
    {
      lnglat: [114.165584, 26.56768],
      name: '井冈山革命博物馆',
      date: '1927.10',               // 可选
      offset: [6, 30],               // 可选，标签偏移
      flagOffset: [-26, -28],        // 可选，红旗偏移
      checked: false                 // 可选，初始打卡状态
    }
  ]
});
```

### 6.3 已实现能力

## 10. 登录与注册

### 10.1 登录页

- 账号支持邮箱/手机号，密码支持显隐切换。
- 表单提交后阻止默认行为，检查非空，800ms 后提示“登录成功”并跳转 `index.html`。
- 没有账号密码校验、没有会话、没有 token。
- 从注册页跳转时带 `?from=register`，显示“注册成功”提示条，5 秒后自动隐藏。

### 10.2 注册页

前端校验规则：

| 字段       | 规则                                   |
| :--------- | :------------------------------------- |
| 用户名     | 至少 2 个字符                          |
| 手机号     | `^1[3-9]\d{9}$`                        |
| 密码       | 8—20 位                                |
| 确认密码   | 必须与密码一致                         |
| 用户协议   | 必须勾选                               |

校验通过后模拟 1 秒请求，提示注册成功并跳转 `login.html?from=register`。注册数据不会保存，登录页也无法识别刚注册的账号。

### 10.3 上线前改造

- 接入真实注册/登录接口，使用 HTTPS 与服务端校验。
- 密码不要明文传输或存储，使用服务端哈希。
- 增加验证码、频率限制、找回密码、会话过期处理。
- 将 Font Awesome 改为本地资源，避免 CDN 不可用导致图标丢失。

## 11. 数据与状态管理

### 11.1 数据来源

| 数据             | 位置                          | 生命周期             |
| :--------------- | :---------------------------- | :------------------- |
| 路线列表         | `routeList.js` 的 `ROUTE_DATA`| 页面加载时           |
| 红色故事         | `splicing.js` 的 `redStories` | 页面加载时           |
| 地图节点         | 各 `*Demo.html` 的配置对象    | 页面加载时           |
| 打卡状态         | `mapReuse.js` 内部对象        | 当前页面，刷新丢失   |
| 后台地点/打卡    | `adminConsole.html` 内数组    | 当前页面，刷新丢失   |
| 预约信息         | 表单 DOM                      | 提交后不保存         |
| 登录/注册        | 表单 DOM                      | 跳转后不保存         |

### 11.2 结论

当前项目是**纯前端演示型应用**：

- 没有统一的数据层；
- 没有接口请求；
- 没有本地持久化；
- 所有业务状态在刷新后重置；
- 多页面之间无法共享用户、打卡、预约等状态。

如果后续要转为可用产品，建议先补一个统一的数据访问层（`api.js`），再逐步替换页面内的硬编码数组。

## 13. 开发规范

以下约定来自 `README.md`，并结合当前代码现状补充。

### 13.1 分支与提交

- `main` 保持可交付；功能分支 `feat/<name>`，修复分支 `fix/<name>`。
- 提交遵循 Conventional Commits：`type(scope): subject`。
- 常用类型：`feat`、`fix`、`docs`、`style`、`refactor`、`chore`。

### 13.2 命名

- README 约定组件目录/文件使用 `PascalCase`，静态资源使用 `kebab-case`。
- 当前实际代码中，JS 文件多为 `camelCase`（如 `routeList.js`），CSS 文件多为 `camelCase`（如 `adminConsole.css`），与 README 存在偏差。
- 建议后续统一为：JS/CSS 使用 `kebab-case`，页面使用 `PascalCase` 或语义化中文名；至少保证同一目录内风格一致。

### 13.3 新增页面检查清单

- [ ] `<!DOCTYPE html>`、`lang="zh-CN"`、UTF-8、viewport 完整。
- [ ] `<title>` 能准确描述页面，不使用 `Document`。
- [ ] 样式优先放入 `src/static/css/`，避免继续复制内联样式。
- [ ] JS 放入 `src/components/Javascript/`，使用 `defer` 或放在 `</body>` 前。
- [ ] 所有图片放入 `src/static/image/`，使用相对路径。
- [ ] 交互元素使用 `<button>` / `<a>`，补充 `aria-label`、键盘焦点样式。
- [ ] 在 1440 / 1024 / 768 三个宽度下检查布局。
- [ ] 浏览器控制台无 404、无 JS 报错。
